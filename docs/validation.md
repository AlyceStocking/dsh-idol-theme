### 修正：桌面版点击无反应（2026-10-19）

- 现象：DSH 桌面版点击背景无反应。排查确认插件与桌宠均已加载（进程、依赖、版本都正常），问题在点击判定：初版把 `[data-slot]`、`[role]` 一并排除，而桌面版宿主把内容区包在带这些属性的容器里，导致所有点击都被判成「非背景」。
- 修正：排除规则收窄到真正的控件与内容——`button/a/input/select/label`、常见交互 `role`、聊天行 `[data-chat-flow]`、输入卡片 `[data-composer-card]`、标题栏与拖拽行、侧栏/右栏/标题栏类名、会话标题与主题自身组件；其余区域视为背景。
- 监听改为 `pointerdown` + `click` 双通道（均在捕获阶段，避免宿主先吞事件），250ms 去重；新增 `Alt+I` 备用快捷键，用于区分「事件没进来」还是「样式没生效」。
- 边界：未能在本会话内模拟真实鼠标点击；若点击仍无效而 `Alt+I` 有效，说明事件被宿主吞掉，下一步改用坐标判定（聊天列矩形之外即背景）。

### 修正二：聊天容器被整体排除（2026-10-19）

- 用户反馈：`Alt+I` 有效、点击无效。说明状态切换与样式都正常，问题仍在判定。桌面版聊天列几乎铺满窗口，用户所点的“背景”大多落在消息列表容器 `[data-chat-flow]` 内（消息之间的留白），而该容器被整体排除。
- 修正：排除项从 `[data-chat-flow]`（容器）改为 `[data-chat-flow-kind]`（单条消息行），消息行内的点击仍不切换，行间留白与列外区域都会切换；监听同时注册到 `window` 的捕获阶段（`pointerdown`/`mousedown`/`click`），避免下游 `stopPropagation` 吞掉事件。
- 状态：已安装 `1.3.0-desktop.5`（`792e85aa…0a53c1`），待用户重启桌面版验证。

### 修正三：可拖动行被排除（2026-10-19）

- 用户提示：桌面版里可以拖动窗口的区域就是点击目标。该区域带 `data-window-drag`，而它此前在排除列表里，因此点在那里永远不会切换。
- 修正：把 `[data-window-drag]` 从排除列表移除（会话标题仍由 `sessionHeaderSelector` 单独排除）；判定从 `pointerdown` 改为「按下记录坐标 → 松开时位移 < 6px、间隔 < 700ms 才算点击」，这样在可拖动行上单击能切换、拖动窗口不会被误判。监听仍在 window 捕获阶段，`pointerdown/up` 与 `mousedown/up` 双通道。
- 安装插曲：本次 `pnpm add` 因 GitHub 依赖 HEAD 超时失败，而旧归档已被清理，导致 profile 短暂指向不存在的文件；已手工把依赖改为新归档后用 `pnpm install --offline` 修复，当前依赖与归档一致。
- 状态：已安装 `1.3.0-desktop.5`（`ce614b1b…28022`），待用户重启桌面版验证。

### 修正四：把聊天卡片算作背景（2026-10-19）

- 用户反馈：点击的“背景”其实就是那张半透明消息卡片，在里面拖动会出现选中文字的效果，说明点击命中的是消息行；而消息行此前被排除。
- 修正：不再排除 `[data-chat-flow-kind]`，整个对话卡片（卡片底、正文、行间留白）都算背景；用「按下到松开位移 < 6px、< 700ms」区分点击与拖动，并在松开时检查 `window.getSelection()`，有文字选中就不切换——因此拖选文字不会误触，单击空白或文字才切换。链接、按钮、输入框、菜单、侧栏、会话标题、输入卡片仍排除；去重窗口放宽到 400ms，避免双击触发两次。
- 状态：已安装 `1.3.0-desktop.5`（`7643ff1e…0c792e`），待用户重启桌面版验证。
- 已知取舍：单击消息正文也会切换视图（只读消息没有单击语义）；双击选词的第一次点击会切换一次，400ms 内的第二次被忽略。
